# 原廠記憶體表核對：模擬器 Control Table

**核對日期**：2026/11/04
**原廠文件**：`Servo Protocol Memory Table - Magnetic Encoding Version.xlsx`（磁編碼 SMS&STS 內存表，解析版 220328）
**核對對象**：`sim/servo_sim.c` 的位址屬性（`attr_of`）、寫入規則（`write_table`）、上電預設值（`sim_add_servo`）

---

## 一、位址屬性

| 位址 | 原廠表 | 模擬器現況 | 結論 |
|---|---|---|---|
| 0x00–0x04 | EPROM，唯讀（韌體版本、0x02 END、型號） | 唯讀 | ✅ 一致 |
| 0x05–0x27 | EPROM，讀寫 | EPROM | ✅ 一致 |
| 0x28–0x30 | SRAM，讀寫 | SRAM 可寫 | ✅ 一致 |
| 0x31 | 表上寫「無定義」 | SRAM 可寫 | ⚠️ 原廠表自相矛盾：0x30 轉矩限制是 2 bytes，0x31 就是它的高位元組。**維持可寫** |
| 0x32–0x36 | SRAM，**無定義，權限「無」** | SRAM 可寫 | ❌ 要改：當成不可寫（寫入靜靜忽略） |
| 0x37 | SRAM，讀寫（Lock） | SRAM 可寫 | ✅ 一致 |
| 0x38–0x45 | SRAM，唯讀（含 0x40 異步寫標誌、0x43–0x44 無定義） | 唯讀 | ✅ 一致 |
| 0x47 以後 | **原廠表沒有列** | 唯讀 | ✅ 依原廠表維持唯讀；但 LeRobot 會寫 0x50–0x55（見 V-15） |

## 二、Lock（0x37）的語意：模擬器做錯了

原廠表原文：

> 寫 0 關閉寫入鎖，寫入 EPROM 地址的值**掉電保存**
> 寫 1 打開寫入鎖，寫入 EPROM 地址的值**掉電不保存**

也就是說，**Lock 不是「能不能寫」，而是「寫了之後會不會存進 flash」**。Lock = 1 時寫入 EPROM 區照樣生效，只是斷電後會恢復成原本保存的值。

| | 模擬器現況 | 原廠表 |
|---|---|---|
| Lock = 1 時寫 EPROM | 靜靜忽略，值不變 | **立即生效**，斷電後消失 |
| Lock = 0 時寫 EPROM | 生效 | 生效，並且斷電保存 |
| 上電預設 Lock | 1 | **0** |

**要改**：
- `write_table`：EPROM 區不再因 Lock = 1 而拒絕寫入
- 每顆馬達多存一份「已保存的 EPROM 映像」：Lock = 0 時寫 EPROM 會同步更新映像；Lock = 1 時只改 table
- 新增測試鉤子 `sim_power_cycle(bus, id)`：table 的 EPROM 區還原成保存的映像，SRAM 回到上電預設值
- 上電預設 Lock 改為 0
- demo 的 Lock 測試改寫：Lock = 1 寫最大角度限制 → 立即生效 → power cycle → 恢復原值；Lock = 0 寫入 → power cycle → 仍保留

**對驅動的意義**：安全層要「暫時」調整角度限制時，可以在 Lock = 1 下寫入，立即生效又不消耗 flash 寫入壽命；只有校正結果這類要永久保存的值，才需要 Lock = 0。這要在 W10 真機確認（V-13）。

## 三、Goal_Velocity = 0 的行為由 Phase 決定

原廠表「特殊字節設置說明」，Phase（0x12）BIT3「速度模式」：

- BIT3 = 0：速度 0 → **停止**
- BIT3 = 1：速度 0 → **最高速**

模擬器現在固定為「速度 0 → 以最高速移動」，等於假設 BIT3 = 1。

**要改**：依 0x12 BIT3 決定。原廠表沒有給 Phase 的初始值，模擬器預設 0x12 = 0（速度 0 = 停止，比較安全），README 的待驗證清單改成「依 Phase BIT3」。驅動端的規則：**永遠明確寫入速度，不依賴速度 0 的行為**。

## 四、上電預設值

原廠表有列初始值、模擬器目前沒設定的，補上：

| 位址 | 名稱 | 原廠初始值 |
|---|---|---|
| 0x0D | 最高溫度上限 | 70 |
| 0x13 | 卸載條件 | 44（= BIT2 過熱、BIT3 過流、BIT5 過載保護開啟；電壓與磁編碼保護關閉） |
| 0x14 | LED 報警條件 | 47 |
| 0x1A / 0x1B | 順 / 逆時針不靈敏區 | 1 / 1 |
| 0x1E | 角度分辨率 | 1 |
| 0x22 | 保護扭矩 | 20 |
| 0x23 | 保護時間 | 200 |
| 0x24 | 過載扭矩 | 80 |
| 0x26 | 過流保護時間 | 200 |
| 0x37 | Lock | **0**（模擬器現為 1） |

原廠表未給值、依版本而異的（0x0E / 0x0F 電壓門檻、0x12 Phase、0x15–0x19 PID 與積分限制、0x1C 保護電流、0x25 / 0x27 速度環係數）維持模擬器預設，留給 W10 的暫存器快照確認。

## 五、其他確認

- 0x18 最小啟動力為 **1 byte**，0x19 是另一個暫存器「積分限制值」。LeRobot 把 0x18 當 2 bytes 讀寫會連帶動到 0x19（`LeRobot-notes.md` 4.6 已記錄，原廠表證實）
- 0x08 應答級別：0 = 除 READ 與 PING 外不回應答包。模擬器已照此實作 ✅
- 0x28 扭矩開關寫 128 = 將當前位置校正為 2048。模擬器未實作，列入「不模擬」
- 0x2A 目標位置範圍 ±32766（BIT15 方向位），與 sign-magnitude 規則一致 ✅

## 新增編號（併入下次 lab log）

**發現**
- **F-15**：Lock（0x37）控制的是「是否存進 flash」，不是「能否寫入」。Lock = 1 時寫 EPROM 仍立即生效，斷電後消失；上電預設為 0
- **F-16**：原廠記憶體表自相矛盾：0x30 轉矩限制標為 2 bytes，0x31 卻另列為「無定義」
- **F-17**：Goal_Velocity = 0 時是停止還是最高速，由 Phase（0x12）BIT3 決定

**待真機驗證**
- **V-13**：Lock = 1 時寫 EPROM 是否立即生效、斷電後是否恢復（例：寫 0x0B → 讀回 → 斷電重開 → 再讀）
- **V-14**：實際 Phase（0x12）值，特別是 BIT3（速度 0 行為）與 BIT4（單圈 / 多圈）。併入 V-08
- **V-15**：0x47 以後（原廠表未列）的實際行為；LeRobot 會寫 0x50–0x55，確認是否可寫、作用為何
