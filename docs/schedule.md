## 重大調整

### 一、STM32 移至下學期（11/03，C-08）

原訂 W14–16 的條件性移植階段取消，W13 判斷點一併移除。STM32 改以個人 side project 形式自主學習，不列入專題交付物。

文獻對照組：A（timer 預設）與 B（timer 調最低）本學期完成；C（STM32 獨立控制）移至下學期。報告敘事為「本學期 PC 端特性量測，下學期補 MCU 對照」。

### 二、期中考期間（W6–W8）無進度

10/14–11/01 三週投入期中考，W6–W8 的驅動工作未執行，10/25 的單軸硬承諾未達成。W6 另有 LeRobot 模擬環境建置（補記於 `week06`）。驅動部分於 W9 補做。

### 三、上層介面凍結（11/04–11/05）

`interface-spec.md` v1.0 凍結交付 B，v1.1 補時鐘規定，v1.2 修正 magic 位元組序、時間戳解析度說明與 seq 重啟死鎖。設計理由另立 `interface-spec-rationale.md`。

### 四、時間戳時鐘定義（11/04–11/05，C-16 → C-19）

兩端一律使用 Unix epoch 牆鐘微秒。Windows 上 Python 須 ≥ 3.13，否則以 ctypes 呼叫 `GetSystemTimePreciseAsFileTime()`。禁用 `QueryPerformanceCounter` 與 `perf_counter`——起點為開機或行程啟動後的任意時刻，跨行程相減無意義。

### 五、方向調整：Python 優先（11/15，C-24～C-28）

手臂第三次延後，這次是**給專題生的手臂尚未組裝**，W11 由學長帶領三人一起裝。

三人共同決定：**本學期以 Python 建立可運行、可對接的系統為主線**，能用現成資源（LeRobot、SDK、標準庫）就用並學會使用；自訂部分（UDP 介面、安全層、主迴圈、延遲量測）自行實作。

C 驅動收在**驗收 A/B 與模擬器**；收包狀態機、驗收 C/D、真機驅動移至下學期。詳見 `lab-log/week09.md`。

這不是推翻 C-07，而是把它的「第一版後端用 LeRobot」從備援提升為本學期主線：

```
         A（VR 顯示） / B（手部感測）
              ↓  interface-spec.md v1.2（凍結，不因本次調整修改）
      ┌───────┴───────┐
  Python 後端        C 驅動後端
  （本學期主線）      （下學期）
```

**介面凍結在此得到實證**：後端換掉，規格零修改，A 與 B 無感。

### W13 的量測範圍（重要）

量的是**控制迴路延遲 `t1 − t0`**：B 橋接蓋章 → 控制層 → 手臂 → 回應包回到控制層。

**不含**實體運動、攝影機、串流與頭盔顯示。完整端到端 `t2 − t0` 需 L10 手臂狀態回傳與影像鏈，兩者都在下學期（C-17）。報告與 meeting 須明確說明量的是哪一段，區段定義見 `system-comm.md` §3.1。

## Python 系統的五步路徑

詳見 `lab-log/week09.md` 第四節。關鍵是**前四步完全不需要硬體**，與當初做模擬器同一個思路。

| 步 | 內容 | 驗證方式 | 需硬體 |
|---:|---|---|---|
| 1 | 綁 49200、收 UDP、印 hex | 用 `interface-spec.md` §7 的發送端當訊號源；應收到 46 bytes | 否 |
| 2 | 拆標頭、驗 magic/version/CRC、印六軸角度 | 對照 §2.3 的 NOP 範例封包與 CRC 檢查值 `0x29B1` | 否 |
| 3 | 固定 100 Hz 主迴圈 + 抽乾佇列只留最新一包 | 量測實際週期抖動 | 否 |
| 4 | 安全層 + 假手臂（二十行 dict） | 送越界角度、壞 CRC、停送 300 ms、送 ESTOP | 否 |
| 5 | 假手臂換成真的 LeRobot bus | 真機 | **是** |

規模約 150–250 行，單一檔案。**不碰** asyncio、多執行緒、類別繼承、numpy、任何框架。

要學的只有三樣：`socket` 的 UDP 收送、`struct` 的 pack/unpack、固定頻率主迴圈，各約一小時。

## 實驗室場次與家中工作的切分

手臂僅一組，且 W11 才組裝完成。原則：**凡需真機者集中同場完成，其餘一律在家做。**

**只有真機能做（依序）**
1. 與學長一起組裝；記錄馬達 ID 設定、7.4V / 12V 版區分、接線順序
2. **`tools/snapshot.py` ← 組好後第一件事**。新組裝的手臂暫存器是乾淨的出廠值，LeRobot 或 calibrate 一跑就改寫，這是唯一一次機會
3. 擷取 PING / READ / WRITE / SYNC 參考封包並存檔
4. 核對兩組電源標示與馬達型號（接電前）
5. 實測 `0x07` 回應延遲是否可改、latency timer 實際值、轉接板是否有 echo（V-06，因 F-20 為高優先）
6. 單包與六軸的往返時間量測
7. 六軸在真實負載下的穩定性
8. 逐條確認 V-01～V-23 與 `sim/README.md` 的待驗證清單

第 3 項是把稀缺的實驗室時間換成可無限重用的資產。

**在家可做**：Python 第 1–4 步、安全層、測試、C 驅動收尾、介面文件、報告、STM32 side project。
