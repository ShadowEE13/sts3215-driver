### 四、時間戳時鐘定義修正（11/04）

原先 `interface-spec.md` 的 Python 範例用牆鐘時間，而 `system-comm.md` 寫控制層用 `QueryPerformanceCounter`——兩者 epoch 不同，相減得到的是時鐘原點差而非延遲，**W12 的延遲量測會算出無意義的數字**。

已修正：兩端一律使用 Unix epoch 起算的牆鐘微秒；Python 用 `time.time_ns() // 1000`（不可用 `time.time()`，Windows 上解析度可能僅約 15.6 ms，比待量的數毫秒迴路還粗），C 端用 `GetSystemTimePreciseAsFileTime()` 換算。規定寫入 `interface-spec.md` §2.4。

### W12 的量測範圍（重要）

W12 量的是**控制迴路延遲 `t1 − t0`**：B 橋接蓋章 → 控制層 → 手臂 → 回應包回到控制層。

**不含**實體運動、攝影機、串流與頭盔顯示。完整端到端延遲（`t2 − t0`）需要 L10 手臂狀態回傳與影像鏈，兩者都在下學期。報告與 meeting 須明確說明量的是哪一段，區段定義見 `system-comm.md` §3.1。

## 實驗室場次與家中工作的切分

手臂僅一組、留在實驗室、採預約制。原則：**凡需真機者集中同場完成，其餘一律在家做。**

**只有真機能做**
1. `tools/snapshot.py`：LeRobot 執行前的唯讀暫存器快照（取得出廠值，程式層級保證唯讀）
2. 跑通官方 LeRobot 範例，建立「已知可運作」基準
3. 擷取 PING / READ / WRITE / SYNC 參考封包並存檔 ← 第 2 項成功後幾乎免費，務必同場完成
4. 核對兩組電源標示與馬達型號
5. 實測 `0x07` 回應延遲是否可改、latency timer 實際值、轉接板是否有 echo（V-06，因 F-20 升為高優先）
6. 單包 WRITE/READ 往返時間量測
7. 六軸在真實負載下的穩定性
8. 逐條確認 V-01～V-18 與 `sim/README.md` 的待驗證清單

第 3 項是把稀缺的實驗室時間換成可無限重用的資產。第 1 項必須排在最前面——LeRobot 一跑就會改寫暫存器，出廠值就取不到了。

**在家可做**：模擬器、驅動實作、介面文件、六軸封包邏輯、測試、報告、STM32 side project。
